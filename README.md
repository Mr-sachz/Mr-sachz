## Overview

Software development focused on building practical tools and systems that automate repetitive work and handle data reliably. Most projects are built with Python and JavaScript. The main focus is browser tooling, local software, background execution and persistent application behaviour.

Started coding in my early teens through Roblox Lua. I worked with scripts, game logic and small systems before moving into broader software development. Since then projects have grown into complete applications and utilities with more attention given to reliability, persistent state and longer running automation.

---

## Projects

Repositories cover browser extensions, Windows utilities, desktop tools, monitoring software, file processing systems and data pipelines.

Some projects are compact utilities built around one clear task. Others combine browser logic with local processing, storage and background execution.

Most are developed beyond the first working version. Debugging, recovery, configuration and edge cases are treated as part of the build rather than something added later.

> `prototype → debug → recover → refine → keep it running`

## Browser and Automation

A large part of the development focuses on software that works across the browser and local system.

This includes extensions with background workers and persistent state. It also includes automated page interaction, data capture, form workflows and session handling. Some tools continue working across tabs or browser sessions without needing constant input.

Other projects cover file processing, scheduled tasks, monitoring and local utilities that remove repetitive steps from larger workflows.

---

## Systems

Larger projects often involve several components rather than one script. That brings in problems such as stale state, failed requests, interrupted execution, duplicate events and malformed input.

```text
predictable behaviour
clean recovery
persistent state
less manual work
```

The aim is simple. Keep behaviour predictable. Recover cleanly when something goes wrong. Reduce unnecessary manual work.

## Background

**LLB Law with Business**

Early learning came from experimenting with Cheat Engine. It provided a practical introduction to how games use memory, values and underlying logic to control behaviour.

Later projects brought different kinds of obstacles. Browser restrictions, changing page behaviour and security controls often meant the obvious solution was not enough. Those constraints pushed development toward better architecture, more reliable state handling and cleaner solutions to difficult technical problems.
